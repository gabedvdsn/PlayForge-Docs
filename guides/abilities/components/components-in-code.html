Components in code

Code finds a component by what it does, not by its class. Find<T>(), on an ability, its spec, an effect, an item and an entity, gives the first of its components that is a T, a kind or an interface it implements.

Capability What it is Implemented by
IAbilityReach An ability's reach. Cast Range
ICooldownModel How an ability's uses come back. Charges

Reach

The targeting tasks, the Creator Lab's bots and your own code read an ability's reach through ForgeReach. So a component of your own that implements IAbilityReach is asked as a Cast Range is.

Cooldown model

An ICooldownModel says how many uses the ability holds, how many are in hand, what a use spends, and why the Cooldown check refuses it with none.

  • An ability with none has SingleCooldown: one use, back as its Cooldown ends.
  • The Cooldown check asks it, the ability spends through it, and a HUD reads it as spec.CooldownModel.

Component state

A component's state that needs its holder, as a Charges component's charges need their ability, is kept with spec.ComponentStates.TryGet and Keep.

No shortcuts

The built-in components are written on this API alone, and PlayForge's core names none of them. So a component of your own reaches as far as they do.

None has a shortcut: code reads one through Find<T>() or the component itself. For example, spec.Find<ToggleAbilityComponent>()?.IsOn(spec) says whether a Toggle is on.
