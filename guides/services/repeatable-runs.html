Repeatable runs

A run that must come out the same twice, as a replay, a rollback or a lockstep match must, needs the same time and the same rolls each time it runs.

  • Time: step the game in fixed steps, with ProcessControl's Fixed Tick Rate (Fixed ticks), or step a world of its own by a fixed time, world.Step(deltaTime). A clock of the game's time follows either.
  • Rolls: put in a SeededRandom, ForgeRandom.Use(new SeededRandom(seed)), seeded for the run, or for each step as a rollback does (Saving and Loading: Rolling back). Unity's random numbers, the default, move whenever anything else in the game draws from them.
  • Cues draw from ForgeCues.Random, numbers of their own, so a run that plays its cues rolls as one that doesn't, as on a server or while a simulation runs ahead, with ForgeCues.Enabled off.
  • Your own code reads time through ForgeTime and draws through ForgeRandom, as PlayForge does: code that reads Unity's Time or Random itself follows neither a clock nor a source put in.
