Pointer input

ForgeInput is what PlayForge reads of the player's input: the press and aim of click targeting, the task libraries' waits for a key or a press, and the Creator Lab's controls.

ForgeInput.Current is the input read now, an IForgeInput: the project's own, ForgeInput.Default(), until code puts another in with ForgeInput.Use(input), which returns the one it replaced; ForgeInput.Use(null) puts the project's own back. The project's own is:

  • InputSystemPointerInput, where the Input System package is installed and the Player settings' Active Input Handling takes it, as it does where it takes both;
  • else LegacyPointerInput, where it takes the Input Manager;
  • else an input that never presses and aims nowhere.
IForgeInput What it says
PointerPressed(button) Whether a button went down this frame: 0 the primary, the left button or a touch; 1 the secondary, the right; 2 the middle
TryGetPointerRay(out ray) The ray the pointer aims along, or false with nothing to aim through, as with no camera
PointerHeld(button) Whether a button is down now
TryGetPointerPosition(out position) Where the pointer is on the screen, in pixels from its bottom left, or false where there's none
ScrollDelta How far the scroll wheel turned this frame, in notches, away from the player positive
KeyPressed(key) Whether a key went down this frame
KeyHeld(key) Whether a key is down now, pressed this frame or held from an earlier one

Only the first two must be written. The rest read as nothing held, no position, no scroll and no key, unless an input gives its own.

What reads it

  • Click targeting, the Select tasks (Position, Direction, GAS Target, GAS Or Position and GAS Target In Range), waits for PointerPressed of its Mouse Button, then aims along TryGetPointerRay (Abilities: Activation).
  • The task libraries' waits: WaitForKey and WaitForAnyKey read KeyPressed, and WaitForPointer reads PointerPressed, in SequenceTaskLibrary and SyncSequenceTaskLibrary alike (Task Sequences: Waiting).
  • The Creator Lab: its presses and keys, the pointer's place, the middle button held to pan and the wheel to zoom (The Creator Lab).

The defaults

Each of the project's own aims through its Camera, or Camera.main where that's null.

  • LegacyPointerInput reads the Input Manager's mouse and keys. It has no pointer position where no mouse is present.
  • InputSystemPointerInput reads the Input System's: a mouse presses each of its three buttons, and a pen or a touch the primary. Its ScrollDelta is the mouse's scroll over 120, a notch on most mice. Its keys are the letters, the top row's digits, F1 to F12, Escape, Space, Return, Tab, Backspace, Delete, the arrows, and left and right Shift, Control and Alt; any other KeyCode reads as never pressed.

Each is compiled only where its input handling is on, so code that names one sits under the same condition: #if ENABLE_LEGACY_INPUT_MANAGER for LegacyPointerInput, and #if ENABLE_INPUT_SYSTEM, with the Input System package installed, for InputSystemPointerInput.

ForgeInput.TryAimThrough(camera, screenPoint, out ray) gives the ray from a camera through a point on the screen: the camera given, or else Camera.main. With neither, it logs a warning of the Input system and returns false. ForgeInput.CameraOr(camera) is the camera given, or else Camera.main, as a floating text faces.

Input of your own

A game with a crosshair, a gamepad's reticle or a controller's ray writes an IForgeInput and puts it in. Give it all seven members, passing those it doesn't change on to the project's own: an input that writes only the two click targeting reads has no key, no pointer position and no scroll, so WaitForKey, WaitForAnyKey and the Creator Lab's keys, clicks and camera hear nothing through it. An input put in stays until code puts another in, past the end of play mode where domain reload is off, so code that puts one in puts back the one it replaced.

using FarEmerald.PlayForge;
using UnityEngine;

// A third-person game's targeting: it presses as the project's own input does, but aims from the crosshair in the
// middle of the screen, through the player's camera
public sealed class CrosshairInput : IForgeInput
{
    private readonly IForgeInput device = ForgeInput.Default();

    public Camera Camera { get; set; }

    public bool PointerPressed(int button) => device.PointerPressed(button);

    public bool TryGetPointerRay(out Ray ray) =>
        ForgeInput.TryAimThrough(Camera, new Vector2(Screen.width * 0.5f, Screen.height * 0.5f), out ray);

    // The rest as the device reads them, so the task libraries' waits and the Creator Lab still hear it
    public bool PointerHeld(int button) => device.PointerHeld(button);
    public bool TryGetPointerPosition(out Vector2 position) => device.TryGetPointerPosition(out position);
    public float ScrollDelta => device.ScrollDelta;
    public bool KeyPressed(KeyCode key) => device.KeyPressed(key);
    public bool KeyHeld(KeyCode key) => device.KeyHeld(key);
}

// Puts it in while the player's camera is on, and gives back the input it replaced
public class CrosshairTargeting : MonoBehaviour
{
    public Camera PlayerCamera;
    private IForgeInput previous;

    private void OnEnable() => previous = ForgeInput.Use(new CrosshairInput { Camera = PlayerCamera });
    private void OnDisable() => ForgeInput.Use(previous);
}
