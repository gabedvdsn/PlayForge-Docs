Time, Randomness, Input and Logging

PlayForge works through four services of its own:

Service What it does
ForgeTime Reads the game's time.
ForgeRandom Draws its random numbers.
ForgeInput Reads the player's pointer.
ForgeLog Says what PlayForge does.

The first three read Unity's own until code puts another in, with ForgeTime.Use, ForgeRandom.Use or ForgeInput.Use. A test, a replay, a server or a game with input of its own does this. Each returns the one it replaced, to put back.

This guide is the reference behind the short sections of Getting Started: Quickstart: a damage ability in ~10 minutes: Time and random numbers on time, logging and profiling. It covers:

  • the clocks, and which one a run takes;
  • the fixed tick;
  • chances and luck;
  • pointer input;
  • log levels;
  • the Profiler's markers and counters;
  • an entity's own services;
  • the small utilities a game's code uses.

In this guide

  • Time: ForgeTime is the clock PlayForge's runtime reads in place of Unity's Time.
  • Clocks: A clock is an IForgeClock, a source of time.
  • Which clock a run takes: Everything PlayForge times goes by a clock, most by their owner's.
  • Picking a clock in an inspector: An inspector picks a clock with an AbstractClockChoice field, as an ability's Run Sequence task's Clock does.
  • Fixed ticks: ProcessControl's fixed tick steps the game in fixed steps of its time.
  • Random numbers: ForgeRandom is where PlayForge draws its random numbers.
  • Chance: ForgeChance rolls every chance PlayForge has.
  • Repeatable runs: A run that must come out the same twice needs the same time and the same rolls each time it runs.
  • Time and rolls in tests: The test kit makes time and chance a test's own, through the same two services (Testing Your Content: The world).
  • Pointer input: ForgeInput is what PlayForge reads of the player's input
  • Logging: ForgeLog is where everything PlayForge says goes.
  • Log levels: A message is let through where its level is at least its system's level.
  • Process and sequence logs: ProcessControl and task sequences have switches of their own, which decide whether they say what they do.
  • Profiling: PlayForge's work shows in Unity's Profiler (Getting Started: Profiling)
  • Entity services: An entity service is a per-entity object that an entity's components share.
  • ForgeHelper: ForgeHelper is a static class of the checks and small sums PlayForge's own systems share.
  • Packet helpers: ProcessTaskUtil holds extension methods for a data packet's targets and the effects it carries.
  • The attribute registry: AttributeRegistry finds an attribute by its name, among those the game's entities have been given.
  • Lists: ReadOnlyListView<T> and ForgeUtils are two small list helpers
  • Sign and math policies: Three enums say how PlayForge reads the sign of a change and turns a number into a factor: ESignPolicy, ESignPolicyExtended and EMathApplicationPolicy.
