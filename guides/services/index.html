Time, Randomness, Input and Logging

PlayForge reads the game's time, draws its random numbers and reads the player's pointer through services of its own, ForgeTime, ForgeRandom and ForgeInput, and says what it does through a fourth, ForgeLog. The first three read Unity's own until code puts another in, with ForgeTime.Use, ForgeRandom.Use or ForgeInput.Use, as a test, a replay, a server or a game with input of its own does, and each returns the one it replaced, to put back. This guide is the reference behind the short sections of Getting Started: Time and random numbers on time, logging and profiling: the clocks and which one a run takes, the fixed tick, chances and luck, pointer input, log levels, the Profiler's markers and counters, an entity's own services, and the small utilities a game's code uses.

In this guide

  • Time: ForgeTime is the clock PlayForge's runtime reads in place of Unity's Time, and where a game puts in a time of its own.
  • Clocks: A clock is an IForgeClock, a source of time: PlayForge has one for Unity's time, one for the game's, an unscaled one, a scaled one and each entity's own, and a game can write its own.
  • Which clock a run takes: Everything PlayForge times goes by a clock, most by their owner's: an effect by the entity it's on, and a sequence's run by the first it finds.
  • Picking a clock in an inspector: An inspector picks a clock with an AbstractClockChoice field, as an ability's Run Sequence task's Clock does: each kind gives the clock for a run on a packet as the run starts.
  • Fixed ticks: ProcessControl's fixed tick steps the game in fixed steps of its time, as many a frame as the frame's time holds, so a run comes out the same at any frame rate.
  • Random numbers: ForgeRandom is where PlayForge draws its random numbers: the game's rolls and random picks all draw from its source, an IForgeRandom.
  • Chance: ForgeChance rolls every chance PlayForge has, each by its ChanceRoll, which says whether it's pseudo-random and whose luck it reads.
  • Repeatable runs: A run that must come out the same twice, as a replay, a rollback or a lockstep match must, needs the same time and the same rolls each time it runs.
  • Time and rolls in tests: The test kit makes time and chance a test's own through the same two services (Testing Your Content: The world).
  • Pointer input: ForgeInput is what PlayForge reads of the player's input: the press and aim of click targeting, the task libraries' waits for a key or a press, and the Creator Lab's controls.
  • Logging: ForgeLog is where everything PlayForge says goes: each message has a level and a system, and a gate on the two decides what reaches Unity's Console.
  • Log levels: A message is let through where its level is at least its system's level: the system's own, where it has one, or else ForgeLog.MinimumLevel, Info by default.
  • Process and sequence logs: ProcessControl and task sequences have switches of their own that decide whether they say what they do, and most of what they say is information, which the level must let through to show.
  • Profiling: PlayForge's work shows in Unity's Profiler: markers that time it, counters that say how much of it there is, and each recorded frame's costliest processes (Getting Started: Profiling).
  • Entity services: An entity service is a per-entity object an entity's components share, made the first time it's asked for and stepped by the entity's own time.
  • ForgeHelper: ForgeHelper is a static class of the checks and small sums PlayForge's own systems share, which a game's workers, conditions and tools can call too.
  • Packet helpers: ProcessTaskUtil holds extension methods for a data packet's targets and the effects it carries, and three loops for async code that wait through ForgeTick.
  • The attribute registry: AttributeRegistry finds an attribute by its name, among those the game's entities have been given.
  • Lists: ReadOnlyListView<T> and ForgeUtils are two small list helpers: a view of a list that foreach walks without allocating, and the index of a list's least or greatest item.
  • Sign and math policies: Three enums say how PlayForge reads the sign of a change and turns a number into a factor: ESignPolicy, ESignPolicyExtended and EMathApplicationPolicy.
