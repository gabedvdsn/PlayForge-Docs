Components

A component is a feature an asset carries in its Components section: an effect's, an ability's, an entity's or an item's.

It hears its asset's moments through hooks, each a no-op it may override. It's the way to add a feature that needs more than one moment, as a mark that pays its caster when the marked one dies.

Each family is a base in the runtime assembly, in FarEmerald.PlayForge:

Base Held by Its context
AbstractEffectComponent an effect's Components EffectComponentContext
AbstractAbilityComponent an ability's Components AbilityComponentContext
AbstractEntityComponent an Entity asset's Components, or a runtime entity's EntityComponentContext
AbstractItemComponent an item's Components ItemComponentContext

Every component also has these members, from AbstractForgeComponent:

Hook When PlayForge calls it
AllowsSeveral As the Components list offers kinds. False, for a kind that makes no sense twice, has the list offer it only while the asset holds none.
Describe() As The Forge's summary and the breakdowns show the component: what it does in one line with its numbers, as "Range 6", beside its name. Null shows its name alone.

Its protected NameOf(asset) gives an asset's name for that line: its PlayForge name, its file's, or "nothing".

Each kind lists its own traps, and Traps, last in this section, lists those every component shares.

In this section

  • Effect components: An effect component adds a feature to an effect, heard at each moment of the effect's life.
  • Ability components: An ability component adds a feature to an ability: it can refuse an activation, make it wait as it winds up, and take over how its cost and cooldown apply.
  • Entity components: An entity component adds a feature to an entity: it hears the entity register, die, revive and end, and can make its abilities wait as they wind up.
  • Item components: An item component adds a feature to an item: it hears the item given, equipped, unequipped, removed and used.
  • State a component keeps: A component keeps what it counts for one holder through its context, never in its own fields.
  • Capabilities other code finds: A component can implement an interface that other code asks an asset for.
  • Traps: These traps apply to every kind of component.
