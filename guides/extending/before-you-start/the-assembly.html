The assembly

A kind of a game's own compiles in an assembly that references PlayForge's.

Code Where it lives What it references
Runtime code Unity's default assembly, or a game's own assembly definition FarEmerald.PlayForge, and UniTask for anything async: an ability task, a wind-up, a process or a sequence task
Editor code, as a validation rule or a drawer An editor-only assembly FarEmerald.PlayForge.Editor as well

The runtime assembly, FarEmerald.PlayForge, is referenced automatically, so scripts in Unity's default assembly see it. A game's own assembly definition lists it among its references.

Two of PlayForge's names clash with others:

  • Attribute. PlayForge's attribute asset is FarEmerald.PlayForge.Attribute, and System.Attribute shares its name. A file with both using System; and using FarEmerald.PlayForge; that writes Attribute doesn't compile.
    • The examples here alias it: using ForgeAttribute = FarEmerald.PlayForge.Attribute;.
  • Editor. The editor's namespace is FarEmerald.PlayForge.Editor. In code inside a namespace under FarEmerald.PlayForge, a bare Editor names that namespace, so write UnityEditor.Editor in full there.
