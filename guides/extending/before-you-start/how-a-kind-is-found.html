How a kind is found

The editor finds a kind of a game's own by its base, so nothing registers a kind: writing the class is enough.

A field a designer picks a kind for is a [SerializeReference] field of an abstract base or an interface. An asset's Components, a stage's Tasks, a worker group's lists and a number field's Kind are such fields.

The field's picker lists every class that derives from the field's type, in any assembly the editor loads. It leaves out a class that's abstract or an open generic.

Give each kind of your own these two things:

  • A public constructor that takes nothing. The picker makes the kind with it as it's picked. The number, condition and Local Data menus list only classes that have one. Another picker lists a class without one, and fails as it's picked.
  • [Serializable], as PlayForge's own kinds are. The condition menu lists only serializable classes.

The constructor runs once for each pick, so it can set defaults of its own over its base's, as CantFallBelowAttributeWorker sets its timing and its sign. Field initializers run with it.
