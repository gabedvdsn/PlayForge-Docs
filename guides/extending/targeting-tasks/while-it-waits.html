While it waits

A task that waits for the player holds its ability in targeting, and the game shows it.

  • The slot says it's choosing. AbilitySpecContainer.IsTargeting is true while a run of the ability waits on its targeting. A game shows the ability's targeting's Prompt beside its name while it is.
  • A task that doesn't wait for the player returns a null Prompt.
  • Another ability can take its place. Another of the entity's abilities may activate on a request that cancels targeting, as a player's press. An ability still choosing then gives way where its While Targeting says it yields.
    • Yields gives way.
    • Entity's Rule follows the entity's Targeting Yields.
    • Holds keeps it.
  • A trigger's request and an activation at start don't cancel targeting: AbilityActivationRequest.CancelsTargeting is off for them. Code that makes a request chooses.
  • Giving way cancels the task's token. Its claim lets go at once, so the other activation starts while the cancelled task winds down. Nothing of the activation is paid, it ends as cancelled, and the task's Clean runs.

So a task awaits with its token, as WaitForPointerPress does. Once its token is cancelled, it files nothing and applies nothing: a pick filed after the token was cancelled lands in an activation that's gone.
