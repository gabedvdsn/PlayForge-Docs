The editor

A game's editor code can check PlayForge's assets, draw a base type of its own as PlayForge draws its kinds, and start new assets from its own templates. This section covers each. The code lives in an editor-only assembly that references FarEmerald.PlayForge.Editor.

Validation rules

The Problems view and each asset's inspector list what the project's rules find (The Editor Tools). A rule of a game's own derives from ForgeValidationRule, with a public constructor that takes nothing, and the validator finds it:

  • Check(Object asset, List<ForgeProblem> problems): adds what it finds in one PlayForge asset.
  • Reads(Object asset): true for an asset the rule reads to check others, so an edit to it has the others checked again.
  • Name: what the Problems view groups its problems under, by default its class's name spaced out without "Rule".

A problem is a ForgeProblem(asset, severity, message, propertyPath), its severity ForgeProblemSeverity.Note, Warning or Error, and its Fix a ForgeQuickFix(name, apply), the button that fixes it.

A rule about one kind of component derives from ForgeComponentRule<T>, which hears each component of its kind an asset holds, whichever kind of asset holds it: Check(Object asset, T component, int nth, string path, List<ForgeProblem> problems), with nth the component's count among its kind and path its place, as "Components.Array.data[1]".

using System.Collections.Generic;
using FarEmerald.PlayForge.Editor;
using MyGame;
using UnityEditor;
using Object = UnityEngine.Object;

namespace MyGame.EditorRules
{
    public sealed class MinimumRangeRule : ForgeComponentRule<MinimumRangeAbilityComponent>
    {
        public override string Name => "Minimum ranges that refuse nothing";

        protected override void Check(Object asset, MinimumRangeAbilityComponent component, int nth, string path,
            List<ForgeProblem> problems)
        {
            if (component.Least == null || !component.Least.IsConstant || component.Least.Constant > 0f) return;
            problems.Add(new ForgeProblem(asset, ForgeProblemSeverity.Warning,
                "Its Minimum Range of 0 refuses no target. Give it a range, or take the component off.", path)
            {
                Fix = new ForgeQuickFix("Set its range to 1", () =>
                {
                    Undo.RecordObject(asset, "Set Minimum Range");
                    component.Least = 1f;
                    EditorUtility.SetDirty(asset);
                }),
            });
        }
    }
}

A rule is asked of every asset each time the validator runs: it returns at once for an asset it doesn't check.

Drawing a base type of a game's own

PlayForge draws its kinds' fields through drawers registered for their bases, so a kind of a game's own is drawn with no drawer of its own. A field whose type is a base of the game's own, as a [SerializeReference] AbstractWeatherRule on a component of its own, takes a drawer made from one of PlayForge's:

  • AbstractTypeRefDrawer<T>: the kind picker and the kind's fields. Its virtual members say which kinds it offers (FilterType, Offers), how it names them (CleanTypeName, GetStringValue), whether it offers None (AcceptClear), and what follows a pick (OnTypeChanged).
  • AbstractGenericDrawer<T>: the same, folding to a line of its values, and naming kinds without the words in TypeNameSuffixes.
  • AbstractWorkerDrawer<T>: a generic drawer that offers no None.
  • AbstractComponentDrawer<T>, for a base made from AbstractForgeComponent: a worker drawer that offers a kind that allows one only while its list holds none.

In the game's runtime assembly, a base of its own and a field of it:

using System;
using UnityEngine;

namespace MyGame
{
    [Serializable]
    public abstract class AbstractWeatherRule
    {
        public abstract float SpeedFactor { get; }
    }

    [Serializable]
    public class RainWeatherRule : AbstractWeatherRule
    {
        [Range(0f, 1f)] public float Slow = 0.2f;

        public override float SpeedFactor => 1f - Slow;
    }

    public class Weather : MonoBehaviour
    {
        [SerializeReference] public AbstractWeatherRule Rule = new RainWeatherRule();
    }
}

In its editor assembly, the drawer, whose picker shows the kind as Rain Weather, "Rule" taken off its name:

using FarEmerald.PlayForge.Editor;
using UnityEditor;

namespace MyGame.EditorRules
{
    [CustomPropertyDrawer(typeof(AbstractWeatherRule), true)]
    public class WeatherRuleDrawer : AbstractGenericDrawer<AbstractWeatherRule>
    {
        protected override bool AcceptClear(SerializedProperty prop) => false;
    }
}

Inspectors, presets and templates

BasePlayForgeEditor is the base of PlayForge's asset inspectors, and the Forge's presets and a project's templates are where new assets start (The Editor Tools). A GameplayEffect field of a game's own marked [ForgeEffectTemplate("Cost")] or [ForgeEffectTemplate("Cooldown")] offers, in its right-click menu, to copy or use the project's Cost or Cooldown template; those are the two keys it knows.
