Targeting tasks

A targeting task picks what an activation acts on before its stages run: it's the ability's Targeting, one task, run as the activation starts. This section covers writing one, and what a task must do while its ability waits on it.

AbstractTargetingAbilityTask (from AbstractAbilityRelatedTask, not marked [Serializable]: mark a task of your own):

Member Is
Activate(data, token) Required. Picks, and files the pick's targeting packet with data.SetTargetingPacket(Tags.TARGET, packet), or several with data.SetTargetingPackets(Tags.TARGET, targets), the first the primary; or calls WhenTargetingInvalid(data).
Prompt The words a game shows while the task waits for the player, as "Click a point on the ground"; null for a task that doesn't wait for the player. PressWords(button) gives "Click", "Right-click" or "Middle-click".
TargetIsValid(...) Which targets it takes: an ITarget, a GameObject, a Transform or a point.
WhenTargetingInvalid(data) Marks the targeting failed and, with Break Runtime On Invalid on (BreakRuntimeOnInvalid), throws OperationCanceledException, which ends the activation as cancelled.
ConnectInputHandler(data), DisconnectInputHandler(data) Hook an input handler of its own as it's prepared, and unhook it as it's cleaned. A false from ConnectInputHandler fails the targeting. An override of Prepare calls the base's last.
IsCriticalSection True: targeting holds the activation's claim.

Its helpers: TryGetDataTarget(data, out target) and TryGetDataPoint(data, out point), a target or a point the activation's data holds already, as an AI's request does; and WaitForPointerPress(button, token), which waits for a press of the game's input, ForgeInput.Current, and gives the ray it aims along, or null with nothing to aim through. AbstractGasTargetingAbilityTask adds Requirements (AvoidRequireTagGroup), which an entity's applied tags must meet.

What follows a task's pick:

  1. The ability's components hear it in CanTakeTarget and may refuse it (Components).
  2. The pick resolves: the entity each packet under Tags.TARGET, or the ability's implicit tag, points at is filed under Tags.TARGET_REAL, where tasks and checks find it.
  3. Where the pick is an entity, the caster's checks and the components' CanStart are asked again, then the Target Checks on the target. Then come the wind-ups, the cost and the first stage.
using System;
using System.Collections.Generic;
using System.Threading;
using Cysharp.Threading.Tasks;
using FarEmerald.PlayForge;
using UnityEngine;

namespace MyGame
{
    [Serializable]
    [ForgeMenu("Picked", Description = "The player clicks the ground, and the enemy nearest the click is the target.")]
    public class ClickNearestEnemyTargetTask : AbstractTargetingAbilityTask
    {
        [Tooltip("How far from the click an enemy may stand, read at the ability's level")]
        [NumberMin(0f)] public ScalableFloat Radius = 2f;

        [Tooltip("The layers the click's ray hits")]
        public LayerMask Ground = ~0;

        [Tooltip("The pointer button that picks: 0 the primary, 1 the secondary, 2 the middle")]
        public int Button;

        public override string Prompt => $"{PressWords(Button)} near an enemy";

        public override async UniTask Activate(AbilityDataPacket data, CancellationToken token)
        {
            // An AI's activation hands its target: take it rather than wait for a click
            if (TryGetDataTarget(data, out var handed))
            {
                if (TargetIsValid(handed)) data.SetTargetingPacket(Tags.TARGET, handed.GetTargetingPacket());
                else WhenTargetingInvalid(data);
                return;
            }

            var ray = await WaitForPointerPress(Button, token);
            if (ray == null || !Physics.Raycast(ray.Value, out var hit, Mathf.Infinity, Ground))
            {
                WhenTargetingInvalid(data);
                return;
            }

            var caster = data.EffectOrigin.GetSource();
            var sides = data.EffectOrigin.GetAffiliation();
            var near = new List<ITarget>();
            ForgeEntities.Within(hit.point, Read(Radius, data), true, near, caster, false);

            ITarget best = null;
            float bestDistance = float.MaxValue;
            foreach (var each in near)
            {
                if (each.IsDead || !ForgeEntities.Takes(EAffiliationFilter.Enemies, caster, sides, each) || !TargetIsValid(each)) continue;
                float distance = ForgeEntities.Distance(each, hit.point, true);
                if (distance >= bestDistance) continue;
                best = each;
                bestDistance = distance;
            }

            if (best == null) WhenTargetingInvalid(data);
            else data.SetTargetingPacket(Tags.TARGET, best.GetTargetingPacket());
        }
    }
}

While it waits

A task that waits for the player holds its ability in targeting, and the game shows it:

  • The slot says it's choosing. AbilitySpecContainer.IsTargeting is true while a run of the ability waits on its targeting; a game shows the ability's targeting's Prompt beside its name while it is. A task that doesn't wait for the player returns a null Prompt.
  • Another ability can take its place. As another of the entity's abilities activates on a request that cancels targeting, a player's press, an ability still choosing gives way where its While Targeting says it yields: its own Yields, or Entity's Rule, which follows the entity's Targeting Yields. Holds keeps it. A trigger's request and an activation at start don't cancel targeting (AbilityActivationRequest.CancelsTargeting is off for them), and code that makes a request chooses.
  • Giving way cancels the task's token. Its claim lets go at once, so the other activation starts while the cancelled task winds down. Nothing of the activation is paid, it ends as cancelled, and the task's Clean runs.

So a task awaits with its token, as WaitForPointerPress does, and once its token is cancelled it files nothing and applies nothing. A pick filed after the token was cancelled lands in an activation that's gone.

Traps

  • No task state. data.GetTaskState<T> takes an ability task; a targeting task keeps what it needs in its Activate's locals.
  • Take a handed target first. An AI's or a replay's activation hands its target in its data; a task that waits for a click whatever the data holds can't be cast by an AI.
  • An exception other than a cancellation fails the activation, written to the Console.
  • The pick is a packet. SetTargetingPacket files a place: an entity's packet points at its entity, and a StaticTargetingPacket(point) at none. An activation whose pick is a point has no target, so its Target Checks don't run.
