Entity services

An entity service is an object of a game's own each entity keeps as it runs, made the first time it's asked for and stepped by the entity's own time: a combo count, a cooldown of the game's own, a respawn's wait. This section covers writing one.

AbstractEntityService:

  • System: the entity it's for.
  • Step(float deltaTime): each frame of the entity's step, with its own clock's time, after its effects.
  • Revive(): as a staying entity revives.
  • End(): as the entity ends, after which it keeps none.

entity.GetService<T>() gives an entity's T, making it the first time; entity.FindService<T>() gives it only where it's made, or null.

using FarEmerald.PlayForge;

namespace MyGame
{
    // A combo count each entity keeps, back to 0 after a pause between hits and as it revives
    public sealed class ComboService : AbstractEntityService
    {
        public float Window = 2f;
        public int Count { get; private set; }
        private float sinceLast;

        public void Hit()
        {
            Count++;
            sinceLast = 0f;
        }

        public override void Step(float deltaTime)
        {
            if (Count == 0) return;
            sinceLast += deltaTime;
            if (sinceLast >= Window) Count = 0;
        }

        public override void Revive() => Count = 0;
    }
}

A worker or a component counts a hit with ctx.System.GetService<ComboService>()?.Hit(), and a number kind reads it with context.SystemOf(NumberSide.Caster)?.FindService<ComboService>()?.Count ?? 0.

  • A service has no inspector: it's made with its constructor that takes nothing, and its settings come from code.
  • A save keeps no service. A loaded entity makes its services again as it's asked for them.
  • Step runs every frame for every entity that has the service: keep it quick, as above, which returns at once while there's nothing to count down. See Time, Input and Logging for PlayForge's other services.
