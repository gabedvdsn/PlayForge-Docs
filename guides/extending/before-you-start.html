Before you start

This section covers what every kind of a game's own shares: the assembly it lives in, how the editor finds it, how its picker names and files it, how its fields show, where it keeps what it counts, and how it's renamed.

The assembly

  • The runtime assembly, FarEmerald.PlayForge, is referenced automatically, so scripts in Unity's default assembly see it. A game's own assembly definition lists it among its references, with UniTask for anything async: an ability task, a wind-up, a process or a sequence task.
  • Editor code, a validation rule or a drawer, lives in an editor-only assembly that also references FarEmerald.PlayForge.Editor.
  • PlayForge's attribute asset is FarEmerald.PlayForge.Attribute, and System.Attribute shares its name: a file with both using System; and using FarEmerald.PlayForge; that writes Attribute doesn't compile. The examples here alias it, using ForgeAttribute = FarEmerald.PlayForge.Attribute;.
  • The editor's namespace is FarEmerald.PlayForge.Editor, so in code inside a namespace under FarEmerald.PlayForge, a bare Editor names that namespace: write UnityEditor.Editor in full there.

How a kind is found

A field a designer picks a kind for is a [SerializeReference] field of an abstract base or an interface: an asset's Components, a stage's Tasks, a worker group's lists, a number field's Kind. Its picker lists every class that derives from the field's type, in any assembly the editor loads, and isn't abstract or an open generic. Nothing registers a kind: writing the class is enough.

  • A public constructor that takes nothing. The picker makes the kind with it as it's picked. The number, condition and Local Data menus list only classes that have one; another picker lists a class without one and fails as it's picked.
  • [Serializable], as PlayForge's own kinds are. The condition menu lists only serializable classes.
  • The constructor runs once for each pick, so it can set defaults of its own over its base's, as CantFallBelowAttributeWorker sets its timing and its sign. Field initializers run with it.

How a kind is named and filed

[ForgeMenu] on the class says where its picker files it and what it's called:

  • [ForgeMenu("Effects")] files it under a submenu, and a slash nests them, as "Effects/Areas". A path holds for the classes made from the one that names it, so a kind of AbstractScaler's is filed under its Scaler submenu unless it names another; [ForgeMenu("")] puts a kind at the top whatever its base names.
  • Name = "..." replaces the class's name in the picker and in the field.
  • Description = "..." is what the picker says while the kind is highlighted.

Without a Name, a picker shows the class's name spaced out, its family's word taken off its end:

Family Words taken off Example
Components EffectComponent, AbilityComponent, EntityComponent, ItemComponent, Component BountyMarkEffectComponent is Bounty Mark
Ability tasks AbilityTask, Task PulseTask is Pulse
Targeting tasks TargetTask, Task ClickNearestEnemyTargetTask is Click Nearest Enemy
Workers, cue handlers, value stages, and the other kinds drawn as workers are Worker, Scaler, Handler, Behaviour, Policy, Rule, Config, Settings, Task, Cue, and a few more GainOnHitWorker is Gain On Hit, AnimatorCue is Animator
Scaler behaviours ScalerBehaviour, Behaviour RoundToStepScalerBehaviour is Round To Step

A number kind takes the name its [NumberKind] gives, and a condition the one its [GameplayCondition] gives (Scalers, number kinds and conditions).

How its fields show

A kind's fields draw under its picker as Unity draws their types: public fields and [SerializeField] ones, each with its [Tooltip]. [HideInInspector] keeps one out. Two attributes show a field only while another field of the same object says so:

  • [ShownWhen(nameof(UsePhysics))] shows it while a bool is on, and [ShownWhen(nameof(Mode), (int)EMode.Area)] while an enum holds one of the values given. Tasks, components, workers, cue handlers and the other kinds a picker makes read it.
  • [ForgeShowWhen(nameof(Mode), EMode.Curved)] does the same in scalers, number kinds and conditions.

A number field of a kind's own is a ScalableFloat or a ScalableInt, limited with [NumberMin], [NumberMax] or [NumberRange]; Unity's own [Min] and [Range] don't work on one (Scalers: A number field in your own code). A tag field takes [ForgeTagContext(...)] to say which tags its picker offers (Tags in code).

One object for every holder

A kind is one object on its asset, shared by every entity the asset reaches: one Burn effect's component serves every burning entity, one ability's task every activation of it. A kind keeps nothing for one holder in its own fields. Each family hands it a place to keep that:

Family Where it keeps what it counts for one holder
Components ctx.GetState<T>(this): one effect application's, one entity's ability's, one entity's, one entity's item's
Effect workers ctx.GetState<T>(this) in its hooks, spec.GetWorkerState<T>(this) elsewhere: one application's
Ability tasks data.GetTaskState<T>(this): one activation's
Targeting tasks, sequence tasks locals of their run, or the run's data packet
Tag and analysis workers the entity: an entity service, or its Local Data
Cue handlers a dictionary keyed by cue.Key ?? cue.Spec

A [NonSerialized] field that caches something of the kind's own, made from its settings, is fine, as Cast Range keeps its Check Range.

Renaming a kind

A kind is saved by its class's name, assembly and namespace. Renaming or moving the class needs Unity's [MovedFrom], or every asset that holds one loses it; the Problems view lists an asset that holds a class it can't find.
