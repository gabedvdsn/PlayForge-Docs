Cue handlers

A cue handler plays feedback, a shake, a sound, an animation, at an effect's, an ability's, an entity's or an item's moments, or where a cue tag routes. This section covers writing one; Cues: Handlers covers where cues are raised and PlayForge's handlers.

AbstractCueHandler's hooks, each a no-op it may override:

Hook Called
Burst(cue) At a moment that plays once. By default it calls OnTicked for a tick, OnRemoved for a removal and OnApplied for any other moment.
OnApplied(cue), OnTicked(cue), OnRemoved(cue) From Burst.
Begin(cue), End(cue) As a lasting cue begins and ends, as a While Active one does.

CueContext holds Target, the entity it plays on; Moment; Tag; Source; Origin; Spec and Ticks, for an effect; Data, an activation's; Magnitude, Point and Normal, where its raiser gave a hit; Key; Lasting; and Transform and Position, the target's object and where it plays. NumberContext.Of(in cue) reads a handler's numbers for it.

Handlers sit in the Cues components' lists, the Play Cue task's, and a cue library's routes. Code plays one with ForgeCues.Burst, ForgeCues.Begin and ForgeCues.End, handed a handler or a list and a CueContext.

using System;
using FarEmerald.PlayForge;
using UnityEngine;

namespace MyGame
{
    [Serializable]
    [ForgeMenu(Description = "Sets an Animator trigger on the one the cue plays on, and a bool while a lasting cue lasts.")]
    public class AnimatorCue : AbstractCueHandler
    {
        [Tooltip("The trigger set as it bursts")]
        public string Trigger = "Hit";

        [Tooltip("The bool on while a lasting cue lasts")]
        public string WhileActive = "Stunned";

        public override void OnApplied(CueContext cue)
        {
            if (!string.IsNullOrEmpty(Trigger) && AnimatorOf(cue) is { } animator) animator.SetTrigger(Trigger);
        }

        public override void Begin(CueContext cue)
        {
            if (!string.IsNullOrEmpty(WhileActive) && AnimatorOf(cue) is { } animator) animator.SetBool(WhileActive, true);
        }

        public override void End(CueContext cue)
        {
            if (!string.IsNullOrEmpty(WhileActive) && AnimatorOf(cue) is { } animator) animator.SetBool(WhileActive, false);
        }

        private static Animator AnimatorOf(in CueContext cue) =>
            cue.Transform != null ? cue.Transform.GetComponentInChildren<Animator>() : null;
    }
}

A runtime entity has no object, so Transform is null on one.

Sinks

A sink decides whether a raise plays at all, as a server's that plays none, or a client's that plays only its own player's: a ForgeCueSink whose WillPlay(ECueEvent cueEvent, in CueRaise raise) says so, given every world as ForgeCues.Sink or one world with ForgeCues.UseSink(world, sink). raise.Cue is the cue, and raise.Source what raised it. ForgeCues.Enabled = false plays none.

Traps

  • A handler is shared: one keeps what a lasting cue placed under cue.Key ?? cue.Spec, which its End hands back, as PlayForge's Prefab cue does. Two lasting cues on one entity each begin and end, so a bool the first End turns off is off for the second too, as in the example: count them where that matters.
  • End can come with no Begin. A muted entity's cues and every cue while ForgeCues.Enabled is off don't begin, and still end, so what began before the mute is taken down. End does nothing where it finds nothing.
  • A sink is asked for End too: it answers an End as it answered its Begin.
  • A cue is presentation alone. A server may play none, so game state never depends on a cue. Rolls come from ForgeCues.Random, the cues' own random numbers, so a cue never moves the game's.
  • A handler that throws is caught and written to the Console, and the cues after it play.
