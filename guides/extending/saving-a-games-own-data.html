Saving a game's own data

A ForgeSnapshot holds what PlayForge saves of an entity, and nothing of a game's own: a game saves its own data beside it. This section covers how, and what a save leaves out; Saving and Loading covers saving and loading.

A snapshot is plain serializable types, so a class of the game's own holds it with the rest:

using System;
using FarEmerald.PlayForge;
using UnityEngine;

namespace MyGame
{
    [Serializable]
    public class GameSave
    {
        public ForgeSnapshot Hero;
        public int Gold;
        public int BestCombo;

        public static string Write(IGameplayAbilitySystem hero, ForgeAssetCatalog catalog, int gold, int bestCombo) =>
            JsonUtility.ToJson(new GameSave { Hero = ForgeSave.Capture(hero, catalog), Gold = gold, BestCombo = bestCombo });

        public static GameSave Read(string json, IGameplayAbilitySystem hero, ForgeAssetCatalog catalog)
        {
            var save = JsonUtility.FromJson<GameSave>(json);
            if (save?.Hero != null) ForgeSave.Restore(hero, save.Hero, catalog);
            return save;
        }
    }
}

What a save leaves out, which a game that needs it saves itself:

  • Local Data, an entity's and its assets'.
  • Entity services, which a loaded entity makes again.
  • Component states, what ctx.GetState<T>(this) keeps.

What a game's code hears of a load:

  • gas.GetCallbacks().OnRestored fires once a load is done (Saving and Loading: What a load does).
  • An effect component's Lend and TakeBack, and an item component's Equipped and Unequipped with Restoring true (Components).

An asset made at run time, or one of the game's own a save names, goes in the catalog with catalog.Add(id, asset) (Saving and Loading: The Asset Catalog). An effect from another entity is saved by that entity's id, through an IForgeEntityIds the game gives Capture and Restore: IdOf(entity) and Find(id) (Saving and Loading: Effects from other entities).
