Attributes

An Attribute asset names one number an entity can have, such as Health, Mana or Strength. An entity is anything that runs a gameplay ability system (GAS), such as the player or an enemy.

Attribute and AttributeSet assets become one CachedAttributeValue per attribute. Every change goes through one of the four verbs.

Health's inspector.

The asset holds no value. An entity gets its starting values for the attribute from its Attribute Set, and gameplay effects change them from there.

At runtime, each entity holds two values for each of its attributes:

Value What it is
Base The value the attribute is measured against. For a pool such as Health, Base is the maximum.
Current The value in play. For a pool such as Health, Current is what is left.

For a stat such as Strength, the two are often the same. The Attribute Set's bounds keep them in range (see Attribute Sets).

Attribute sets, effects, validation rules and workers refer to the attribute asset itself. An attribute has no asset tag.

Each section below matches the inspector section of the same name. A collapsed section shows one line about what it holds, such as the abbreviation or how many assets use the attribute.

In this guide

  • Identity: The Identity section names the attribute and says what it is.
  • Roles: A game's settings live on its Forge Project, the asset at the root of its folder that The Forge's projects are.
  • Local Data: Local Data is a list of named values stored on the asset.
  • Used By: The Used By section lists the PlayForge assets that refer to this attribute, each with its type icon
