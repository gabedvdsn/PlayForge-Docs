Task Sequences

A task sequence is a workflow over time, built in code. Its stages run one after another, and each stage is a set of tasks run together.

An ability runs as a task sequence. So can anything with steps: a projectile's flight, a channel, a cutscene, a tutorial, a boss's phases.

A sequence runs as a process (Processes), so ProcessControl starts, pauses and ends it like any other.

Tip

The Task Sequence Examples sample shows every part of this guide in code. It also has a component that runs any example from a scene.

In this guide

  • The parts: A task sequence is built from five parts: sequences, stages, tasks, injections and chains.
  • Building one: You build a sequence in code, stage by stage, with TaskSequenceBuilder.
  • Waiting: A sequence can wait as a stage, inside a task, or on the player's input.
  • Repeating: A sequence, or one of its stages, can repeat.
  • Changing the run: You can change a run from one of its tasks, from outside, or by a condition, as far as the sequence allows.
  • Time limits and endings: A run can have time limits, and handlers that hear how it ends.
  • Clocks: A run's time is its clock's.
  • Running one: You can run a sequence as a process, in place, or through a runtime of your own.
  • Chains: A chain runs its sequences in order, with one data packet.
  • Synced sequences: A synced runner is the same sequence stepped a frame at a time, with no async.
  • The libraries: Two libraries hold ready-made tasks, one for async stages and one for synced ones.
  • Logging: What a sequence says goes through ForgeLog, under its own system, Sequences.
  • Built-in kinds: The kinds PlayForge ships for this guide's pickers, each with its menu and what it does, as its picker says.
