Gameplay Effect & Attribute Pipeline

This page describes how a GameplayEffect becomes an attribute change, stays correct while it lives, and reverses when it dies, under the two-kind impact model.

It is the authoritative description of the runtime pipeline. If code and doc disagree, one of them has a bug: file it either way.

All paths are relative to Assets/PlayForge/Runtime/PlayForge/.

In this guide

  • 1. The model in one page: Every authored impact is an AttributeImpactEntry on GameplayEffectImpact.Entries, and its delivery makes it one of two kinds of change: a modifier or a commit.
  • 2. Attribute state (CachedAttributeValue): Each attribute's runtime state is a CachedAttributeValue, whose ActiveValue is derived from that state
  • 3. The four-verb attribute API (AttributeSystemComponent): Every attribute mutation funnels through one shared 4-phase pipeline (CommitWithCarrier)
  • 4. Effect lifecycle (EffectSystemComponent): One shared component owns the shelf.
  • 5. Recalculation (regulated attributes): A regulated attribute is recomputed when an attribute it depends on changes.
  • 6. Initialization & auto-scaling: Attributes initialize as their set is provided, and an auto-scaling attribute's Current follows its Base
  • 7. Entry derivation (no asset migration): The first entry is derived, never serialized. The effect's impact quad + duration flags are its authored surface.
  • 8. Verification: The golden tests in Assets/PlayForge/Tests/Editor/PlayForgeGoldenTests.cs pin this pipeline.
