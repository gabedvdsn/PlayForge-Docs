Preferences and Project Settings

PlayForge has two settings pages: Project Settings → PlayForge, the settings a project shares, kept in assets under version control, and Preferences → PlayForge, each user's own. This section covers both, and the logging level.

Project Settings → PlayForge

The page opens with which PlayForge this is, its version, package name and the Unity it needs, as its package.json says, and a row of links: Guides, the documentation site; Editor Tools, this guide; API Reference; and Changelog, the package's CHANGELOG.md. Each site link's tooltip is its address. Then its settings:

  • PlayForge Folder: where a new Forge Project goes, each in a folder of its own, and the Bootstrap prefabs; Assets/PlayForge to start. … picks a folder in Assets. It's the Unity project's own setting, in ProjectSettings/PlayForge.asset.

The rest is the active Forge Project's, kept in its asset, so each game has its own. With no project active, the page says so: choose one in The Forge, or, while the Unity project has none, Create Forge Project makes one named for the game.

  • Forge Project: what the project's game reads as it runs, through its GameRoot. Roles, the attribute playing each role, by its tag (Attributes: Roles); Crowd Control, the rules an entity follows where it names none (Abilities: Crowd Control); Cue Library (Cues: Routes); Resolve Order (Effects: Resolve Order); Combat Log (Entities: Combat Log); Purge Levels (Effects: Purging); and Workers, every entity's (Workers: Where workers come from). Fill Roles by Name gives each of PlayForge's roles no attribute plays, Health, Luck and Movement Speed, the project's attribute of that name, Move Speed for Movement Speed too, as one Undo step.
  • New Assets: each type's folder within the project's, which The Forge and a field's New put its new assets in; … picks one inside the project's folder. Use Default Folders puts each back.
  • Defaults: for each type, its New Asset, which a new asset of the type starts as a copy of, and its Import, the assets the Import window lists first.
  • Cost and Cooldown: the Cost Effect and Cooldown Effect, which an ability's Cost and Cooldown fields offer to copy or use, and an Active item copies.
  • Templates: the project's own assets that Create offers to start a new asset as a copy of.

Each edit is saved in the project's asset, and Undo takes it back.

PlayForgeSettings reads and writes the project's authoring settings: FolderFor(type), NewAssetDefault(type), ImportDefaults(type), UsageEffect(key) and SetUsageEffect(key, effect), SetNewAssets, SetDefaults, UseDefaultFolders() and DefaultFolder(type). UseProject(project) reads another project's in place of the active one's, and gives back the one it replaced. EffectTemplateRegistry gets and sets the Cost and Cooldown effects by their keys, "Cost" and "Cooldown". The settings themselves are the project's ForgeProjectSettings, the authoring ones its ForgeAuthoringSettings.

Preferences → PlayForge

  • Tags: Show Full Tag Paths, off to start, shows a tag's whole path in strong text, in place of its parents in secondary text before its leaf. Group Tags by Root, on to start, groups the tag picker's tags under their root.
  • Menus: Menu Width, 360 to start, from 220 to 1200, and Menu Height, 420 to start, from 160 to 1600: the most a PlayForge dropdown grows to, a picker's or a field's menu. A longer list scrolls.
  • Logging: Minimum Log Level, the quietest message PlayForge logs: Verbose every trace, Info notable events, Warning and Error problems alone, and None nothing. Info to start.
  • Use Defaults puts every preference back, the tables' column widths and hidden columns and the log level among them.

Preferences are kept in EditorPrefs, for each user. PlayForgePreferences holds them, and its UseDefaults() does what Use Defaults does. ForgeLogSettingsBridge keeps the log level and gives it to ForgeLog.MinimumLevel after each domain reload: its CurrentLevel, SetLevel(level) and ResetLevel(). A build logs Info unless code sets ForgeLog.MinimumLevel (Getting Started: Logging). A double click on a message ForgeLog wrote, in the Console, opens the code that logged it, not ForgeLog.
