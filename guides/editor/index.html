The Editor Tools

PlayForge's editor tools make a game's assets, check them and watch them at work: The Forge lists a Forge Project's assets beside their inspectors, the inspectors and their fields edit them, the Problems view says what's wrong with them, and the Debugger shows the entities and processes as the game plays. This page covers each tool in depth, with the editor types behind it, in FarEmerald.PlayForge.Editor, and the Creator Lab's in FarEmerald.PlayForge.Lab.Editor. Getting Started: Tooling tour's Tooling tour is the short version.

In this guide

  • Menus and shortcuts: This section lists where each tool opens from.
  • The Forge: The Forge (TheForge) is PlayForge's main window: the active Forge Project's assets in a list, beside a detail pane that shows the one selected.
  • Forge Projects: A Forge Project (ForgeProject) holds one game's PlayForge assets and its settings: it's an asset, and the assets in its folder are the project's.
  • New assets and presets: The Forge's Create makes an asset of any type it lists, blank or from a preset, ready to fill in.
  • Templates: An asset can take another of its type as its template, as a prefab instance takes its prefab: it's the template's child, takes the template's fields when the template is pushed, and keeps the fields it overrides.
  • Renaming, duplicating and deleting: This section covers what a rename changes, and what Duplicate and Move to Trash do.
  • The Tags view: The Forge's Tags shows the active project's tags in place of its assets: those its assets and its Tag Library use, those no asset uses, and those code exposes.
  • Inspectors: PlayForge draws an inspector of its own for each of its assets, the same in the Inspector and in The Forge's detail pane.
  • Import and Clear: A section's Import copies chosen fields into the asset from another, and its Clear resets the section; the asset menu's Import from Another Asset... imports the whole asset.
  • Fields and drawers: PlayForge's property drawers draw its fields wherever they're shown: in its own inspectors, in the Inspector of a component, and in an inspector of your own built with UI Toolkit.
  • Number fields: Every number a PlayForge asset authors is a number field, a ScalableFloat or a ScalableInt, which ScalableFloatDrawer and ScalableIntDrawer draw.
  • The Problems view and validation: PlayForge's validator checks every PlayForge asset in the Unity project as it changes, and keeps what it finds; the Problems view lists it.
  • The Debugger: The Debugger (RuntimeDebugger, Window → PlayForge → Debugger) shows the game as it plays, and changes its entities as it shows them.
  • Preferences and Project Settings: PlayForge has two settings pages: Project Settings → PlayForge, the settings a project shares, kept in assets under version control, and Preferences → PlayForge, each user's own.
  • Spreadsheets: Spreadsheets write a project's numbers by level, or its items' stats, to CSV, and read a sheet back.
  • The Creator Lab: The Creator Lab is a scene for trying a project's own assets: units, test dummies, and its time in your hands.
  • Build verification: BuildVerification proves that PlayForge's runtime compiles and links in a player, with no editor code in it, as a build server would check.
  • Editor helpers: The types in this section are public pieces PlayForge's editor builds on, which an editor script of your own can use too.
