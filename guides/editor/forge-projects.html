Forge Projects

A Forge Project (ForgeProject) holds one game's PlayForge assets and its settings: it's an asset, and the assets in its folder are the project's. This section covers the project asset and its folder, which assets belong to which project, the active project, and moving assets between projects.

The project and its folder

New Project…, in The Forge's project menu, asks for a Name and makes a project in a folder of its own under the PlayForge Folder, as Assets/PlayForge/Arena/Arena.asset, and makes it the active one. With it, it makes:

  • the project's Game Root entity, in its GameRoot folder: the game's own entity, on the System side, which the project's GameRoot runs as;
  • the Bootstrapper, GameRoot and ProcessControl prefabs, in the PlayForge Folder's Bootstrap folder, where they're missing. A Bootstrapper that plays no project plays the new one.

The name starts as the game's product name, from Player Settings, without its spaces. Bootstrap, the prefabs' folder, can't be a project's name. Create Forge Project, where there's none, does the same. Create → PlayForge → Forge Project makes the project's asset alone, in the folder the Project window shows.

The PlayForge Folder is Assets/PlayForge until Project Settings → PlayForge sets another. Where it's the folder PlayForge's own code is in, or a folder inside it, projects and Bootstrap go in a folder beside the code's, named for it, as Assets/PlayForge Projects, so the code's folder never holds a project's files.

A type's new assets go in its folder within the project's, which is made as the first one is: Abilities, Effects, Items, Attributes, AttributeSets, Entities, Scalers, Requirements, Pipelines, Modifiers and Rules, until Project Settings → PlayForge says otherwise. A type The Forge doesn't list, as a Tag Library, goes in the project's folder itself.

The project's inspector (ForgeProjectEditor) shows its Description, its Settings, its Game Root Entity and Keep Catalog Current, and a line in place of its catalog's entries, as "Names 166 assets for saves, kept current as they're made, moved in and deleted". A project is the asset catalog its saves read: each PlayForge asset made, copied or moved into its folder is named in it by its GUID as it lands, a deleted file's entries go, and an asset moved out stays named, so a save made before still finds it. A project also catches up on the assets it doesn't name yet as it's imported, and once each editor session. With Keep Catalog Current off, the catalog is left as it is (Saving and Loading: The Asset Catalog).

Which assets belong to which

An asset belongs to the innermost project whose folder holds it, so one project's folder can hold another's. A project at the root of Assets holds every asset no other project does. An asset in no project's folder is in no project.

The Problems view checks each asset against its own project's settings: its roles for an ability's attribute costs, its Cue Library for a Cue Tag cue. A game as it runs reads its settings from ForgeProject.Current: the project code gives ForgeProject.Use, or else the one its GameRoot names, and never the editor's active one, so Play mode reads what a build does.

The active project

The active project is the one The Forge shows, chosen in its project menu, or in the Creator Lab's Project. Each user keeps their own, for each Unity project. Until one is chosen, it's the project at the root of Assets where there is one, or none, where The Forge shows the assets in no project. While the Unity project has no Forge Project, every asset counts as the active project's.

The active project decides:

  • what The Forge lists, what its Tags view and its counts of uses read, and what the Creator Lab's library holds;
  • what each pick of assets offers: an asset field's picker, Set Template..., a number field's Scaler Assets, the Import window's sources, Import Values… and Pick an Unlinked Effect...; and which tags a tag picker offers;
  • where a new asset goes, and whose settings Project Settings → PlayForge shows and edits.

Moving and copying

Move to Project and Copy to Project, in the asset menu, list the projects other than the active one: each selected asset goes into its type's folder in the one chosen, with a number added to its file's name where another file has it. A moved asset is named in its new project's catalog and stays named in its old one's; a copy is named in its new project's.
