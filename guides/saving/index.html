Saving and Loading

ForgeSave saves an entity at rest and loads it back.

  • ForgeSave.Capture takes what lasts on an entity into a ForgeSnapshot.
  • ForgeSave.Restore puts it back, on the entity it came from or on a fresh one of the same kind.

A snapshot is plain serializable types, so a game writes it where it likes, through JsonUtility or its own serializer.

// Save
ForgeSnapshot save = ForgeSave.Capture(gas, catalog);
string json = JsonUtility.ToJson(save);

// Load
ForgeSnapshot loaded = JsonUtility.FromJson<ForgeSnapshot>(json);
ForgeSave.Restore(gas, loaded, catalog);

Only a hub built from an entity can be saved or loaded:

  • a GameplayAbilitySystem with its Entity asset;
  • a RuntimeGameplayAbilitySystem made from an identity.

In this guide

  • The Asset Catalog: An Asset Catalog names the assets a save refers to, and finds them again.
  • What a save holds: A save holds what lasts on the entity.
  • What a load does: A load puts the save back in four steps.
  • Effects from other entities: An effect knows what applied it: an entity, or one of its abilities or items.
  • Rolling back: A rollback saves each step, and on a late input loads a step back and runs again.
  • Copying an entity: ForgeSave.Copy(from, onto) copies what lasts on one entity onto another, as a mirror clone takes its original's state.
  • Versions: Each save names the format it was written in.
