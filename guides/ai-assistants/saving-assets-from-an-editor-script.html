Saving assets from an editor script

When the person asks for assets they won't make by hand, an editor script builds them, and a batch run calls it with -executeMethod. Save each as The Forge's Create does: in its Forge Project's folder for its type, named, with the asset tag its name gives.

  • The Forge Project. Ask the person to make it in The Forge, which offers to make the first. Code can't name one: in a Unity project with none, the first asset ForgePresets.Make saves makes one named after the Unity project. ForgeProject.Folders() lists each project with its folder.
  • An asset with a preset, as Create → Gameplay Effect → Damage: ForgePresets.Make(preset, name), with the preset from ForgePresets.For(type), as ForgePresets.For(typeof(GameplayEffect)).
  • Any other asset, as below. Its asset tag is its kind, then its name's words capitalised and joined: Tag.Generate("Effect.FireballDamage", "FireballDamage"). The kinds are Effect, Ability, Entity, Item and AttributeSet.
  • A picker's label names its class: the class's name spaced out, less its family's word (Extending PlayForge: Before you start: How a kind is named and filed). Return Damage Attribute is ReturnDamageAttributeWorker, Select Gas is SelectGasTargetTask, and Stack Bounds is StackBoundsConfig. A [ForgeMenu] attribute's Name gives some a label of their own, so search the source for the label too.
  • A template. SetTemplate alone copies nothing. Copy the template into the new asset with EditorUtility.CopySerialized, give the asset its own name and tag, then call SetTemplate(template). Change the asset's own fields, then call ForgeTemplatePropagator.UpdateOverrides(asset) and ForgeTemplatePropagator.CaptureInitialListSnapshots(asset). They keep those fields as the asset's own when ForgeTemplatePush.PushToChildren(template) hands the template's changes down.
  • A scene. EditorApplication.ExecuteMenuItem("GameObject/PlayForge/Bootstrapper") adds the Bootstrapper to the active scene, in a batch run too. A new scene unloads saved assets that nothing in the scene uses, so load them again by path after EditorSceneManager.NewScene.

This script saves an attribute where The Forge would, then checks it:

using System.Collections.Generic;
using System.Linq;
using FarEmerald.PlayForge;
using FarEmerald.PlayForge.Editor;
using UnityEditor;
using UnityEngine;
using ForgeAttribute = FarEmerald.PlayForge.Attribute;

namespace MyGame.EditorTools
{
    public static class ArenaAssets
    {
        [MenuItem("Tools/Arena/Make Strength")]
        public static void MakeStrength()
        {
            // The Forge Project the person made, by its name
            var project = ForgeProject.Folders().Select(each => each.Project).First(each => each != null && each.name == "Arena");
            var strength = Save<ForgeAttribute>(project, "Strength");
            strength.Name = "Strength";
            strength.Textures = new List<TextureItem>();
            EditorUtility.SetDirty(strength);
            AssetDatabase.SaveAssets();
            foreach (var problem in ForgeValidator.Check(strength)) ForgeLog.Warning(problem.Message, strength);
        }

        // A new asset where The Forge's Create puts its type: the project's folder for it, the file its name without spaces
        private static T Save<T>(ForgeProject project, string name) where T : ScriptableObject
        {
            string within = PlayForgeSettings.FolderFor(typeof(T), project);
            string folder = within.Length == 0 ? project.Folder : $"{project.Folder}/{within}";
            if (!AssetDatabase.IsValidFolder(folder)) AssetDatabase.CreateFolder(project.Folder, within);
            var asset = ScriptableObject.CreateInstance<T>();
            AssetDatabase.CreateAsset(asset, $"{folder}/{name.Replace(" ", "")}.asset");
            return asset;
        }
    }
}
