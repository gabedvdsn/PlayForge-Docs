Testing with the test kit

The test kit, FarEmerald.PlayForge.Testing, runs a live PlayForge for each test. It steps the player loop a frame at a time, and checks afterwards what must always hold (Testing Your Content).

A project's tests need an assembly definition of their own:

{
    "name": "MyGame.Tests",
    "references": [
        "FarEmerald.PlayForge",
        "FarEmerald.PlayForge.Testing",
        "UniTask",
        "UnityEngine.TestRunner",
        "UnityEditor.TestRunner"
    ],
    "overrideReferences": true,
    "precompiledReferences": [ "nunit.framework.dll" ],
    "autoReferenced": false,
    "defineConstraints": [ "UNITY_INCLUDE_TESTS" ]
}
  • Every platform, not the Editor alone. The kit's tests are PlayMode tests, which step the real player loop.
  • Add the game's own assembly to references, where the game's scripts have an assembly definition.
  • Run them in the Test Runner's PlayMode tab, or with the editor closed: Unity.exe -batchmode -projectPath <project> -runTests -testPlatform PlayMode -testFilter MyGame.Tests -testResults <results.xml> -logFile <log>. A test run quits by itself, so leave out -quit.

A test derives from ForgeTest, and its body runs through Live, as Making assets in code shows. World makes entities on either hub, Hub.Mono or Hub.Runtime, and plays them: Hit, Cast, Use and Hold. It reads them with Value, Base, Has, Stacks and HasTag. Frames steps time: Step(n), Seconds(s) and Until(condition, frames, what).

  • The game's saved assets load through AssetDatabase, so a test that plays them is the editor's, under #if UNITY_EDITOR. World.FromIdentity(hub, identity) makes an entity from a saved EntityIdentity.
  • Play them under their project's settings, as its roles, with ForgeProject.Use(project): a test's world plays no project of its own. Give back the project it returns as the test ends.
  • An entity's starting abilities are its own already: start one with World.Use. World.Cast gives the ability first, and fails for one the entity has.
  • A results file's asserts="0" is Unity's, for every test. Its times are short too: each frame lasts a fixed game time, and the frames run as fast as the machine can.
