Checking the work

Check each change in this order:

  1. It compiles. Unity compiles as its editor takes focus. With the editor closed, a batch run compiles the project, and its log has an error CS line for each error: Unity.exe -batchmode -quit -projectPath <project> -logFile <log>. Never start a batch run on a project that's open in the editor.
  2. Its assets have no problems. The Problems view, Window → PlayForge → Problems, or the count in The Forge's toolbar, checks every asset as it changes. Most problems have a quick fix.
    • In a batch run, -executeMethod FarEmerald.PlayForge.Editor.ForgeValidator.LogAll writes each problem to the log as [PlayForge problems] <path>: <message>, then how many there are.
    • In editor code, ForgeValidator.Check(asset) checks one asset, and ForgeValidator.All holds every problem, each with its Message and its quick fix, Fix.
    • LogAll checks the whole Unity project, samples included. To report on the assets you made, Check each one.
  3. It plays as it should. A test of the test kit's plays it frame by frame (Testing with the test kit).
  4. Look in Play mode. The Debugger, Window → PlayForge → Debugger, shows each entity's attributes (Current, then Base), its effects, abilities and tags, and a timeline of each cast. You can't see it: ask the person to look, and say what to check.

PlayForge's own golden tests check the install: the Test Runner's EditMode tab, FarEmerald.PlayForge.Tests.Golden, or a batch run's -executeMethod FarEmerald.PlayForge.Tests.PlayForgeGoldenTests.RunAll.
