Using PlayForge with an AI assistant

This guide is for an AI coding assistant working in a Unity project that uses PlayForge, and for the person who points the assistant here. It is for PlayForge 1.0.0.

It gives an assistant what it needs before it writes PlayForge code: a map of the framework, what's authored in The Forge and what's written in code, the main tasks as code that compiles, how to check the work, and the rules assistants most often get wrong.

The guides it links, as Effects, ship with PlayForge in its Documentation folder: Assets/Plugins/PlayForge/Documentation from the Asset Store, or Library/PackageCache/com.faremerald.playforge/Documentation from git. Read them there, or on the docs site. The API reference is at https://gabedvdsn.github.io/PlayForge-Docs/api/index.html.

In this guide

  • Setting up your assistant: This guide is one Markdown file, which you download and keep in your project.
  • The map: PlayForge is a gameplay framework for Unity 6, modelled on Unreal's Gameplay Ability System
  • Authored or written: Most of a game made with PlayForge is assets
  • A scene that runs PlayForge: A scene that runs PlayForge has these
  • Applying effects and reading attributes: An effect is applied from an origin: the entity, ability or item it comes from.
  • Making assets in code: An asset made in code is a ScriptableObject, made with ScriptableObject.CreateInstance<T>(), its fields filled as its inspector fills them.
  • Saving assets from an editor script: When the person asks for assets they won't make by hand, an editor script builds them, and a batch run calls it with -executeMethod.
  • Checking the work: Check each change in this order
  • Testing with the test kit: The test kit, FarEmerald.PlayForge.Testing, runs a live PlayForge for each test.
  • Rules assistants get wrong: Attribute is two types. PlayForge's attribute asset, FarEmerald.PlayForge.Attribute, shares its name with System.Attribute.
