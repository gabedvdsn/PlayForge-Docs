The Tags view

The Forge's Tags, in its toolbar (Window → PlayForge → The Forge), lists the active Forge Project's tags and what uses each, declares a tag for contexts, and renames it. The list holds the tags the pickers offer, each by its leaf, or its whole path while Show Full Tag Paths is on; For, the contexts it's for; and Uses, how many of the project's assets use it, a Tag Library among them. Each column sorts, and the search finds a tag by any part of its path.

A tag selected shows in the detail pane: its leaf, with its whole path under it, and its padded name, where it's unique, on hover; its For and its Uses; Declared For, the contexts its Tag Library entry declares it for, with those its code exposes it for checked and locked; and a row for each of the project's assets that uses it, with the fields that do, which shows that asset in The Forge. Choosing a context in Declared For declares the tag for it at once, one Undo step; taking every one away takes the declaration away, so the tag is for the contexts its uses are in alone.

Renaming a tag

A row's Rename…, in its right-click menu, or F2, asks for a tag's new Path, then renames the tag, and every tag under its path with it, in every ability, effect, item, entity, attribute set, attribute, Scaler asset, Value Pipeline and Requirement Template that stores one, and in the Tag Library entries that declare them, as one Undo step. A unique tag stays unique, and a plain one plain. Nothing else follows: code, scenes and prefabs, a Forge Project's settings, Crowd Control Rules, Effect Modifiers, a Cue Library and the Creator Lab's rules keep the old name.

It refuses a path a tag has already and one of PlayForge's own tags' text, and it renames no tag that is, or has under it, one of PlayForge's own or an asset's own tag.

Asset tags follow their names

An asset's own tag follows its name. Renaming an ability, an effect, an item, an entity or an attribute set, by its Name, F2 in The Forge or its asset menu's Rename…, stores the tag its new name gives and carries it into each asset a tag's rename reaches that stored the old one (Renaming a tag), unless another asset still has the old tag as its own, as the asset it was duplicated from does. Where an asset's stored tag isn't the one its name gives, its Identity section shows it in warning text with Update, and the Problems view warns of it, under "Asset tags their names don't give", with the quick fix Store the Tag; each stores the tag and carries it the same way.
