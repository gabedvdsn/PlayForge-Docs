Traps

Tags invite a few mistakes, each below with its way out.

  • Text makes a plain tag. "State.Stunned" where a tag is asked for, and Tag.Generate, give the plain tag of the path, but New Tag made a unique one, and the two are different tags: neither equals the other, answers a query for it in any mode but Same Root, or is heard by the other's listener. Write Tag.GenerateAsUnique("State.Stunned"), or expose the tag from code so that designers pick that very one.
  • An absent tag weighs −1. GetWeight, GetTagWeight, and GetMatchingWeight in Exact mode give −1 for a tag the entity hasn't got, not 0. Ask for more than 0, or use TryGetWeight.
  • A tag added to the cache doesn't last. TagCache.AddTag is dropped at the next compile, as an ability starts or an item changes. Grant a lasting tag with AddLooseTag.
  • A requirement row counts tags, not weights. An Exact entry's Greater Than 1 never passes in a row but While active. Ask for stacks with the Tag Weight check, a Tag condition or a tag worker.
  • A tag shows by ToString(). Its Name is padded where it's unique, and it's the Name a tag converts to where a string is asked for.
  • A tag's relatives are plain. Child, GetParent, GetAncestors and GetRoot make plain tags, which no unique tag equals. Compare families by path, with IsChildOf or a match mode.
  • A rename reaches assets, not code. The Tags view renames what assets store, so a tag the project's code writes keeps its old text there: rename it in the code too.
  • The applied list is the cache's. GetAppliedTags() changes as tags come and go; copy it to keep it.
