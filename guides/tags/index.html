Tags

A tag is a name in a tree, such as State.Stunned under State. PlayForge uses tags to name whatever it matches by name.

Each entity's TagCache holds weights, listeners and tag workers. Show a tag with ToString(), its DisplayName, never its raw Name.

PlayForge names these with tags:

  • what an entity carries, such as Stunned while a stun lasts;
  • what an ability, an effect or an item is, by its asset tag and its context tags;
  • an entity's sides;
  • a gameplay event, a kind of impact, a cue and an attribute's role;
  • the keys of an activation's data, and of an asset's Local Data.

Requirements, crowd control, conditions and workers read the tags an entity carries.

This page covers what a tag is, and how a project makes, declares and finds its tags in the editor. It also covers how an entity holds its tags and tells their changes, and what reads them.

In this guide

  • What a tag is: A tag, a Tag, is a path of names joined by dots, parents first.
  • PlayForge's own tags: Tags holds PlayForge's own tags, each a unique tag in a static property.
  • Contexts: A context is a kind of tag, such as Granted, Event or Local Data Key.
  • The Tag Library: A Tag Library asset, ForgeTagLibrary, declares tags for contexts, so those contexts' pickers offer them before any asset uses them.
  • Tags written in code: Code makes a tag of a path with Tag.GenerateAsUnique, and offers it to the editor's pickers with [ForgeTagExposed].
  • Tag field attributes: Attributes on a Tag field, or on a list of tags, say what its tag field offers and does.
  • The tag field: Each Tag field, alone or in a list, draws as a tag field, TagDrawer.
  • The Tags view: The Forge's Tags view lists the active Forge Project's tags and what uses each.
  • How an entity holds tags: An entity carries the tags its sources grant it, each with a weight.
  • Hearing tags change: An entity's TagCache tells each change to a tag's weight.
  • Querying tags: A match mode, ETagMatchMode, says which of an entity's tags answer for the tag it's asked about.
  • Requirements: Tag requirements are the tags an entity must have, and must not have, for an ability to activate and run, or for an effect to land, go on and come off.
  • Crowd control: Crowd control stops abilities by the tags their caster carries.
  • Conditions and checks: Besides requirements, conditions, ability checks, tasks and triggers read tags: an entity's, or an asset's.
  • Tag workers: A tag worker, AbstractTagWorker, acts while its entity's tags meet its requirements, as flames shown while Status.Burning weighs 3 or more.
  • The editor's tag registry: ForgeTagRegistry, in the editor, is what the tag pickers, the Tags view and New Tag know of the project's tags.
  • Traps: Tags invite a few mistakes.
