Tags

A tag is a name in a tree, as State.Stunned under State, and PlayForge names with tags whatever it matches by name: what an entity carries, as Stunned while a stun lasts; what an ability, an effect or an item is, by its asset tag and its context tags; an entity's sides; a gameplay event, a kind of impact, a cue and an attribute's role; and the keys of an activation's data and of an asset's Local Data. Requirements, crowd control, conditions and workers read the tags an entity carries. This page covers what a tag is, how a project makes, declares and finds its tags in the editor, how an entity holds its tags and tells their changes, and what reads them.

In this guide

  • What a tag is: A tag, a Tag, is a path of names joined by dots, parents first: Status.Debuff.Burn is under Status.Debuff, which is under Status, its root.
  • PlayForge's own tags: Tags holds PlayForge's own tags, each a static property, unique, that the editor's pickers offer for its kind.
  • Contexts: A context is a kind of tag, as Granted, Event or Local Data Key, and a tag field takes the kinds its ForgeTagContext attribute names: its picker offers the tags of those kinds, and the Universal ones.
  • The Tag Library: A Tag Library asset, ForgeTagLibrary, declares tags for contexts, so those contexts' pickers offer them before any asset uses them, and keeps the project's own contexts.
  • Tags written in code: Code makes a tag of a path with Tag.GenerateAsUnique, and offers it to the editor's pickers with [ForgeTagExposed].
  • Tag field attributes: The attributes a Tag field, or a list of tags, takes say what its tag field offers and does.
  • The tag field: Each Tag field, alone or in a list, draws as a tag field, TagDrawer, which shows its tag by its display name and picks another from the tags its contexts offer.
  • The Tags view: The Forge's Tags, in its toolbar (Window → PlayForge → The Forge), lists the active Forge Project's tags and what uses each, declares a tag for contexts, and renames it.
  • How an entity holds tags: An entity carries the tags its sources grant it, each with a weight: the number of grants of it the entity holds now.
  • Hearing tags change: An entity's TagCache tells each change to a tag's weight, to listeners on that tag and on the tags above it.
  • Querying tags: A match mode, ETagMatchMode, says which of an entity's tags answer for the tag it's asked about.
  • Requirements: Tag requirements are the tags an entity must have, and must not have, for an ability to activate and run, or for an effect to land, go on and come off.
  • Crowd control: Crowd control stops abilities by the tags their caster carries, so no ability has to list Stunned among the tags it must not have.
  • Conditions and checks: Besides requirements, conditions, ability checks, tasks and triggers read tags: an entity's, or an asset's.
  • Tag workers: A tag worker, AbstractTagWorker, acts while its entity's tags meet its requirements, as flames shown while Status.Burning weighs 3 or more.
  • The editor's tag registry: ForgeTagRegistry, in the editor, is what the tag pickers, the Tags view and New Tag know of the project's tags: each tag, and each use of it, by context.
  • Traps: Tags invite a few mistakes, each below with its way out.
