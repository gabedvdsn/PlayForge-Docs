Logging

All the runtime says goes through ForgeLog, whose level you control.

  • In the editor, set the level in Preferences → PlayForge → Logging: Verbose, Info, Warning, Error or None.
  • In builds, set ForgeLog.MinimumLevel from code.

Some output is said only when asked, and it's information:

  • ProcessControl's lifecycle logs, while its inspector's toggles are on;
  • a sequence's or a chain's logging;
  • a debug tool's output.

For such output, the toggle makes it, and the level shows it.

ForgeLog.Exception logs an exception as Unity's own LogException does, its stack in the console.

A double-click on a message ForgeLog wrote opens the code that logged it, not ForgeLog. ForgeLog's methods are marked [HideInCallstack], so the Console's Strip Logging Callstack leaves them out of the stack. A logging wrapper of your own marked so is skipped too.

Each message is of a system (ForgeLog.ESystem): effects, abilities, numbers, processes, sequences, saves, input and the rest.

  • A system can take a level of its own, as ForgeLog.SetLevel(ForgeLog.ESystem.Effects, ForgeLog.ELevel.Verbose), or give it back with null.
  • ForgeLog.Logged hears each message let through, with its system, and the entity it's about where it names one. The Creator Lab's Log page hears messages this way.
