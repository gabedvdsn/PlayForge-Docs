Tooling tour

  • The Creator Lab (Window → PlayForge → Creator Lab) — a space to try the project's own assets in: put units and test dummies down, drop effects, abilities and items on them, and read any asset's numbers level by level. It opens in a new scene and plays; its time pauses, steps and speeds up on its own. The Creator Lab.
  • The Forge (Window → PlayForge → The Forge, or Alt+Shift+F, which focuses its search) — every PlayForge asset of the active Forge Project in one list beside a detail pane. A Forge Project is a folder with a project asset at its root (Create → PlayForge → Forge Project), and holds the assets under it that no project inside it does. New Project makes one at once in a folder of its own under the PlayForge Folder, Assets/PlayForge until Project Settings → PlayForge sets another, as Assets/PlayForge/Arena/Arena.asset, with its Game Root entity in Arena/GameRoot; with no project, The Forge asks for the first. The toolbar holds Back and Forward, which go over the assets it has shown, as a browser's do, the project menu, which switches projects and makes a new one, Create, a filter for each PlayForge asset type and More, which holds the filters of the rest, Scaler assets, Requirement Templates, Value Pipelines, Effect Modifiers and Crowd Control Rules, then Tags, the search and the problem count. Create makes an asset of a type: Blank, or from a preset under it, each ready to fill in: a Damage, Damage over Time, Buff, Debuff, Stun (granting the tag of the project's crowd control rule that stops every ability) or Aura effect; an On-Hit or Active item (the Active one with an ability of its own, its cost and cooldown copies of the project's Cost and Cooldown effects); a Passive ability, which activates as its entity starts and gives its holder its effects; or a Hero, with an attribute set of the attributes playing the project's roles, Health first. The project's own Templates follow, each a new asset's copy. A new asset goes into the active project, in its type's folder within the project's, as Arena/Abilities; the first one made with no project makes one named for the game, in a folder of its own. With projects and none chosen, the active one is the project at the root, or none, when The Forge shows the assets in no project. The asset menu moves or copies the selected assets into another project, and renames an asset, as F2 on the list does: its name as its inspector gives it, with the tag the name gives and the file following, or the file of an asset with no name of its own. Every asset picker, an object field's among them, offers the active project's assets alone, and the tag picker the tags they use. The Demo's assets are a project of their own. Its window menu's Spreadsheets writes the project's numbers by level, or its items' stats, to CSV, and reads a sheet back, listing its changes before it makes them (Spreadsheets). The list's columns sort, Summary among them, which shows each asset's one line, as its inspector's header does; a click shows the asset's inspector in the detail pane, under its summary: its description, then a line for each of its sections, or for a Scaler asset or a Requirement Template, of its parts. A double click shows it in the Project window, and a row of an asset's Used By opens that asset in The Forge. Tags lists the project's tags and what uses each. A context is a kind of tag, as Granted, Event, Impact Type or Local Data Key, and a tag field's picker offers the kinds it takes. A tag used in a field of several contexts is for each of them, alone, so each one's fields offer it. A tag's Declared For declares it for contexts, so their fields' pickers offer it, in a Tag Library asset (Create → PlayForge → Tag Library), made where Project Settings puts new assets while there's none. A Tag Library belongs to no Forge Project: every library in the project is read, wherever it sits, so one library can serve them all. New Tag's Contexts start as its field's, and another chosen declares the tag for it. A path that is one of PlayForge's own tags' text, as Blocked or Health, would make that very tag: New Tag says so, and offers it with Use It. A contexts field's New Context… makes a context of the project's own, which the Tag Library keeps and every contexts field offers; a field in the project's own code takes it with [ForgeTagContext("…")]. A tag written in code, a static Tag field or property, reaches the pickers marked [ForgeTagExposed(...)], under the contexts it names, or under Code; one not marked stays out. The Tags view renames a tag, as F2 or a row's Rename… does, and the tags under its path with it, everywhere they're stored; an asset's own tag follows its asset's name instead.
  • Debugger (Window → PlayForge → Debugger) — the game as it plays, in four views the toolbar switches between. Entities lists every entity, of either kind, beside the one selected: its attributes with what changed them, its effects with the time each has left and where it came from, its abilities with their state and cooldown, its tags with what grants them, and its combat log, newest first, a click on a hit showing its breakdown. It acts on the entity too: select a row, and the foot row under its table acts on it. Set an attribute's base and current values (a double-click on a value goes to its field), apply an effect or take one off, grant an ability and activate or interrupt it, or add a tag by name or from the project's tags (a loose tag, which Remove takes back). With Follow Selection on, it shows the entity you select in the scene. Processes lists every process with its state and how long its steps take, and pauses, resumes or terminates the one selected. Tags shows every tag the entities hold, as a tree, and who holds the one selected. Timeline records, as the game plays, each run of an ability, stage by stage, each refused activation, each effect's time on the shelf and each effect refused, and draws them over the last seconds, a track for each entity's ability or effect. Select a track to see an ability's stages and their tasks, with when the selected run reached each, beside its runs, or an effect's applications and refusals, with its journal under them: each landing, tick, hit and removal, and each worker that ran, by its hook and side, with what it queued. A click on a journal entry shows its parts, and a click on a hit in the combat log its steps. Record pauses it, and Clear forgets it. Docked in a narrow column, each view's list sits above its detail. The window menu sets how often it reads the game.
  • Asset fields — every reference to a PlayForge asset is Unity's object field. Open beside it shows the asset in a window of its own; New, beside an empty one, asks the new asset's name in The Forge's New dialog, starting as the asset that holds the field and the field's, then makes it where Project Settings → PlayForge puts its type. An effect field's right-click menu has its template, a pick of the effects nothing links, and New Linked Effect, which names the effect in the New Asset window and links it to the asset.
  • Import and Clear — each inspector section's header has Import, Clear and Help. Import opens the Import window: choose a source on the left, the type's defaults first, then the assets of the type; the right lists the fields that differ, each checked, beside their values now and the source's. Uncheck a field to leave it. A list is replaced, unless its row's Add is on, which adds the source's items after its own. Import N Changes is one Undo step. The asset menu's Import from Another Asset... does the same for the whole asset, which keeps its name, description, icons, asset tag, template and level link. A Workers section's import lists every asset that has a worker group, whatever its type. Clear resets the section's fields at once, and Undo takes it back.
  • Templates — an asset's menu Set Template... picks, from a searchable list of the other assets of its type, the template it becomes a child of; an asset that takes it as its template isn't listed. A child takes the template's fields when the template is pushed, with the template's asset menu Push to Its Children, as one Undo step, and keeps each field it overrides: an edit to a child's field makes it the child's own, and its inspector marks it as Unity marks a prefab instance's override. A marked field's right-click menu has Revert to Template. Saving a template changes no child.
  • Settings — Project Settings → PlayForge shows the active Forge Project's settings, kept in its asset under version control, each game its own: where each type's new assets go, within the project's folder, a new asset's file its name alone; each type's defaults (the asset a new one starts as a copy of, and the assets Import lists first); the effects a new Cost or Cooldown copies; its Templates, which The Forge's Create offers beside PlayForge's presets; and what its game reads through its GameRoot as it runs, the roles its attributes play, by tag, and its default crowd control (Attributes: Roles). Its PlayForge Folder is where a new Forge Project goes. With no Forge Project, Create Forge Project makes one named for the game, in a folder of its own there. Preferences → PlayForge holds your own view toggles, the most PlayForge's dropdowns grow to (Menu Width and Menu Height), and the log level. The Forge's window menu opens both.
  • Golden tests (the Test Runner's EditMode tab, FarEmerald.PlayForge.Tests.Golden) — the framework's behavioral contract; run after upgrading.
  • The test kit (FarEmerald.PlayForge.Testing) — play your own abilities, effects and items in your own tests: a live world for each test, stepped a frame at a time, entities on either hub, Cast, Use, Hold and Hit, scripted time and rolls, and checks after each test that nothing leaked. Testing Your Content sets it up.
  • Problems (Window → PlayForge → Problems) — every problem the validator finds in the project's PlayForge assets, such as a link with no provider, an impact that never applies or a field that reads a scaler it hasn't got, with its severity and its asset; a click selects the asset. By Rule, in its toolbar, groups them under the rule each breaks: where one step fixes a problem, its row has a Quick Fix, as Store the Tag, and its rule a Fix All, each one Undo step. Its linter reads what the project's assets give each other: a stacking effect's periodic number that reads its own stacks, an item's stacks read in an effect no item applies, a filter's impact type nothing deals, and a trigger on an event nothing sends, which is a Note, as code may send it: the view lists notes under a filter of their own, and the counts leave them out. An inspector's header counts its asset's problems. In batch mode, ForgeValidator.LogAll writes them to the Console, a note as a plain line. Add a check of your own by deriving from ForgeValidationRule: override Name to name its group, and give a problem a step that fixes it with its Fix.
