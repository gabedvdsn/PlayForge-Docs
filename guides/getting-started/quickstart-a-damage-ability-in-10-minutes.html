Quickstart: a damage ability in ~10 minutes

Everything below can be done from Window → PlayForge → The Forge (its Create menu), or via the Create → PlayForge asset menu, which lists the Forge Project, then the assets The Forge lists, in its order, then the numbers, rules and the Tag Library.

  1. Attribute — create Attribute asset "Health".
  2. AttributeSet — create a set; add an element for Health with Base/Current 100, Overflow policy ZeroToBase (Current can never exceed Base — pool-style).
  3. EntityIdentity — create one; assign the AttributeSet, set level range.
  4. GameplayEffect "Fireball Damage" — Duration policy Instant; impact: Attribute = Health, Operation = Add, Magnitude = -30 (or attach a scaler for per-level values like −20/−30/−40/−50).
  5. Ability "Fireball" — add a targeting task (e.g. SelectGasTargetTask), one stage with an ApplyEffectsAbilityTask referencing the damage effect; assign Cost/Cooldown effects if desired; set the level range and link the damage effect's scaler LockToLevelProvider.
  6. Scene — add a GameplayAbilitySystem to a GameObject, assign the EntityIdentity, and bring PlayForge up with a Bootstrapper: the prefab PlayForge makes in Assets/PlayForge/Bootstrap as your first Forge Project is made, or a GameObject with the component, naming the Forge Project the scene plays. It makes ProcessControl and the GameRoot, which runs as the project's Game Root entity. Grant + activate the ability through the AbilitySystemComponent, or drive everything from code with RuntimeGameplayAbilitySystem (no GameObject needed), which ProcessControl.Register(gas).Run() starts.

Code-driven abilities (sequences)

For behavior beyond declarative tasks, use RunSequenceTask pointing at a static [TaskSequenceMethod] builder. Load the effects it applies with a SetEffectsTask asset loader, and annotate the sequence so tooltips/analysis can decipher it:

[TaskSequenceMethod("Ability: Chain Lightning")]
public static TaskSequence ChainLightning() =>
    TaskSequenceBuilder.Create("Chain Lightning")
        .WithAppliedEffects(Tags.EFFECTS, maxApplications: 4, "per enemy struck")
        .WithAnnotation("Chains to up to 4 nearby enemies")
        .Task(async (d, t) => { /* ... d.TryApplyEffects(target, Tags.EFFECTS) ... */ })
        .BuildSequence();

Running a process or a sequence

ProcessControl.Register starts a registration, and Run makes it: it registers the process, a MonoBehaviour or runtime process, a TaskSequence or a chain of them, and starts it. HandledBy names what the process belongs to, which ends it as it ends, and With the packet it carries. Left out, an ability's packet hands the process to the packet's source, and anything else to GameRoot. A refused registration says why:

var result = ProcessControl.Register(projectile).HandledBy(gas).With(data).Run();
if (!result) ForgeLog.Warning($"Not registered: {result.Refusal}");

A process an ability's Create Mono Process task spawns takes the ability as its origin, so the effects it applies are the caster's, at the ability's level. Its Spawn At puts it at the caster, as a projectile, or at the ability's target, as a fire on the ground, or where the data's Position says. A gameplay mono process, as ProjectileMonoProcess, carries attributes of its own in Attributes: each is an attribute, the role it's read by (a projectile reads its speed as ProjectileSpeed), and where it starts: its own value, a number or a scaler read at the spawning ability's level, the caster's attribute, or the caster's where it has one. The data that spawns it can set one under its role, and its code reads and sets them with TryGetRole, SetRole, TryGetAttribute and SetAttribute.

A process that requires control waits after it registers; relay.Run() starts it.

Processes covers processes, their lifecycles, pausing and groups, and Task Sequences task sequences: their stages, tasks, repeats, injections, chains, synced runners and libraries.

Time and random numbers

PlayForge reads time through ForgeTime and draws random numbers through ForgeRandom, which read Unity's Time and Random unless you put in your own: ForgeTime.Use(clock) with an IForgeClock, and ForgeRandom.Use(new SeededRandom(seed)), whose rolls repeat from their seed whatever else draws from Unity's. Each Use returns what it replaced, to put back. Each entity numbers its effects' applications (GameplayEffectSpec.ApplicationId) and its abilities' activations.

Each entity also has a clock of its own, gas.GetClock(): the game's time scaled by its TimeScale. Its effects run by it, its cooldowns among them, and so do its abilities' waits and sequences, so TimeScale = 0.5f slows one entity and no other. A scale of 0 holds the entity's time still; it isn't a pause.

A sequence can run by a clock of its own: WithClock(UnscaledClock.Instance) runs a pause menu's while the game's time stands, a ScaledClock runs one at a pace of its own, and a packet's Clock, an entity's among them, comes before either. An ability's Run Sequence task picks one in its inspector, its Clock. Task Sequences has the order a run takes them in.

For a run that comes out the same at any frame rate, set ProcessControl's Fixed Tick Rate, as 60. The game then steps in ticks, each a fixed step of its time, as many a frame as the frame's time holds: every process steps once a tick, its end of frame with it, and each sequence's wait goes on by the tick. Code of your own that waits for a sequence's next frame awaits ForgeTick.Next(token). 0, the default, steps once a frame. The ticks stand with the game's time, so a sequence on the unscaled clock waits for Unity's frames instead.

Tooltips: what does this ability do?

AbilityInspector.Build(ability) returns a full static breakdown — every effect, its role, target scope, and per-level numbers evaluated through the real scaler pipeline, and its components, what sets it off on its own, its chance to activate and its Attribute Costs:

var breakdown = AbilityInspector.Build(fireball);
foreach (var line in breakdown.Describe(level))   // "Deals 30 Health to target", "Cooldown: 8s"
    tooltip.AppendLine(line);

var impact = breakdown.GameplayUsages.First().Series.Impacts[0];
string perLevel = impact.FormatTotal();           // "20/30/40/50"
