A kind of number of your own: one class with one method. Override Evaluate(in NumberContext) to work out the kind's value from what the context offers, and Describe() for the field's one-line summary. Name it, file it and say what it reads with NumberKindAttribute, and the kind menu offers it in every number field whose context provides what it reads:

[Serializable]
[NumberKind("Distance to Target", Reads = NumberReads.Caster | NumberReads.Target)]
[ForgeMenu("Space", Description = "How far the target is from the caster")]
public class DistanceToTarget : NumberKind
{
    [Tooltip("Along the ground, leaving height out")]
    public bool Flat = true;

    protected override float Evaluate(in NumberContext context)
    {
        var from = context.Caster.GetTargetingPacket().position;
        var to = context.Target.GetTargetingPacket().position;
        if (Flat) from.y = to.y = 0f;
        return Vector3.Distance(from, to);
    }

    public override string Describe() => "the distance to the target";
}

A kind is a scaler, so it also works wherever a scaler does: inside a Group, a Conditional or a Clamped, and in an effect's magnitude. The base answers the scaler's carrier methods by building a NumberContext and calling yours. It reads no values per level. Its fields draw in the inspector with no editor code, as a scaler's do, with [Tooltip] and [ForgeShowWhen].

A kind is saved by its class's name, so renaming the class needs Unity's [MovedFrom], as any [SerializeReference] value does. Test one without an effect through For(ISource, ITarget, int, int).
