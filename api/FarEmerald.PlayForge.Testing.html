AllocationMarker

Runs after every other Update, so it marks where ProcessControl's stepping has finished and the test runner's coroutine tick is about to begin.

AllocationProbe

Measures allocation with Unity.Profiling.ProfilerRecorder, because the GC API returns 0 under Mono. Unity's "GC Allocated In Frame" counter reads live within a frame, so an operation is the counter's change across it. Dispose it as the test ends.

A frame takes more care, because the counter's own total for a frame is noisy: 450 to 532 bytes with nothing running, shifting at random. Sampling every player loop stage shows why. All of that lands outside the player loop, in the editor's work between frames, except 40 bytes from the test runner's coroutine tick. So a frame here is the counter's change from the player loop's first stage to its last, less that tick, measured on the same frame. A clean frame reads exactly 0, with no baseline to calibrate, and a baseline would be worse than noise: taken while the noise ran high, it would hide real allocation.

The cost is that anything allocated in a coroutine goes unmeasured with the test runner's. PlayForge's stepping runs in Update and its async work in UniTask continuations, which are measured.

Now and then a burst of a kilobyte or so landed on a few frames at random, whatever was running. It was the editor's Build Report REST service, which listens on a port of its own: where another editor holds that port, as one open beside a batch run does, it tries again about once a second on a thread of its own, and each try allocates about 4 KB, which the counter takes as the frame's. Most frames are short, so a try rarely landed in one, but among 500 entities, whose frames fill most of a second, nearly every measure took one. A probe ends those tries (FarEmerald.PlayForge.Testing.AllocationProbe.EndRestServiceRetries()). Other noise may still land, and it doesn't repeat, where real allocation does, so a measure that isn't clean is taken again and the cleanest stands. A leak fails every attempt.

EffectConfig

What Effect(string, EffectConfig) builds. Each field is the plain default unless a test needs otherwise.

ForgeTest

The base of a test that plays PlayForge content: a live ForgeTestWorld before each test, and after it the world's invariants audited and the world ended. A test is a PlayMode [UnityTest] whose body runs through Live(Func<UniTask>), from a frame's end:

[UnityTest]
public IEnumerator Burn_ticks_twice() => Live(async () =>
{
    var health = Make.Attribute("Health");
    var target = World.Entity(Hub.Runtime, Make.Set(Make.Pool(health, 100f, 100f)));
    var burn = Make.Effect("Burn", new EffectConfig { Policy = EEffectDurationPolicy.Durational, Target = health,
        Magnitude = -10f, Duration = 1f, PeriodicTicks = true, Ticks = 2 });
    World.Hit(World.Entity(Hub.Runtime), target, burn);
    await Frames.Until(() => World.Value(target, health) <= 80f, 90, "two ticks land");
});

A test with a base class of its own makes a world with Start(float) instead.

ForgeTestWorld

One live PlayForge for one test: a real ProcessControl and GameRoot brought up by the real Bootstrapper, stepped by Unity's player loop a frame at a time. It makes what a test needs, entities on either hub, from an identity asset or from attributes, and plays them as a game does: Hit(IGameplayAbilitySystem, IGameplayAbilitySystem, GameplayEffect) applies an effect, Cast(IGameplayAbilitySystem, Ability, IGameplayAbilitySystem, int) gives an ability and starts it, Use(IGameplayAbilitySystem, Ability, IGameplayAbilitySystem) starts one the entity has, and Hold(IGameplayAbilitySystem, Item, int) equips an item. Its Clock(float) and Rolls(params float[]) make time and chance the test's.

It ends as a test asks, or as it's disposed (await using): every process it began, every object and asset it made, and the framework's static state, so tests run in any order. Audit() first says what broke of its Invariants. ForgeTest makes one for each test, audits it and ends it. Step frames, and let ProcessControl step what runs: never call a process's update by hand.

FramePulse

Counts the phases Unity ran, so FrameStepper can show a frame was a whole one.

FrameStepper

Steps the real player loop a frame at a time, so a test can say "this takes exactly N frames". A step ends at the frame's last player loop stage, once FixedUpdate, Update and LateUpdate have all run, so a test only ever looks at finished frames.

Time is captured: every frame lasts exactly DeltaTime and runs one FixedUpdate, however fast the machine is. Unscaled time doesn't follow, so anything timed on it stays on the wall clock. WaitForEndOfFrame never resumes under -nographics, which is why a step waits on a player loop stage instead.

Invariants

What must hold after every test, whatever it did. ForgeTest checks these after each test, so a test gets them without asking, and a test about something else still catches a leak: every observed entity's attribute parts sum to its value, what each dealt is what its targets received, and no process is left running.

ScriptedRandom

Rolls that come out as the test writes them, one after another and round again, and how many were drawn, as Rolls(params float[]) sets them. A chance below a roll misses, so 0 always lands and 0.99 almost never does.

SteppingClock

A clock whose frames each take a fixed step, as Clock(float) sets one.

TestAssets

Builds PlayForge's assets in code, for one test world: attributes, sets, identities, effects, items and abilities, each ready to use. Everything it makes is destroyed with the world, and the tag names it gives are unique within it. A game's own assets, loaded from the project, are the test's to load.
